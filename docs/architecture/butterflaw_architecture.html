Butterflaw 🦋 architecture

A DevOps agent that predicts whether a deployment will break production, using Hindsight memory of every past deployment, root cause, and its own wrong predictions. Five diagrams: system architecture, preflight flow, learning loop, "Ask why" flow, and what a memory looks like.

1. System architecture

Three layers: a single-page UI, a FastAPI backend holding the agent logic, and two external services. Hindsight is the only long-term memory; there is no local vector store or embedding code.

2. Preflight flow: "Seen this before?"

What happens when an engineer describes a deployment before shipping it. Both verdicts come back side by side, so the value of memory is visible on every request.

3. The learning loop (the replay)

24 deployments are replayed in chronological order against a fresh memory bank. Each prediction is made before the outcome is known; then the real outcome, and a review of the agent's own prediction, is retained. Accuracy is computed from these real predictions.

4. "Ask Butterflaw" and closing the loop

After a preflight, the engineer can ask why it warned them (answered by Hindsight reflect over the whole bank), and later record what actually happened so the memory keeps growing.

5. What one memory looks like (example)

Every retain call sends natural-language content plus a timestamp, context and metadata. Hindsight extracts facts and entities from it, links them in a graph, and consolidates repeated facts into observations.
